# RAW 마지막 서머리·통계 검증

검증일: 2026-09-14. 격리된 로컬 PostgreSQL 16 컨테이너를 사용했으며 운영 DB에는 접근하지 않았다.

## DB 실행 및 기능

- 기존 커밋의 `execute("select :value", ...)`는 실제 psycopg2에서 SyntaxError를 재현했다. 기존 SQL 표기를 유지하고 execute 경계에서 바인딩 형식만 변환했다.
- 합성 RAW parsed/원천 각 60,000행(20개 설비, 20,000개 lot), EUV parsed/원천 각 100,000행을 사용했다.
- DIE Yield 합계 20,000, Root Cause 빈도 합계 100,000을 확인했다.
- 로그 24행의 SQL 집계 결과, 건수 일치, STATISTICS_RECORDED, created_at을 확인했다.
- INSERT를 의도적으로 실패시켜 앞서 실행한 DELETE가 되돌아가지 않음을 확인했다. 두 메서드는 별도 커밋이다.

## 시간 비교

아래 수치는 DELETE와 INSERT를 각 서머리 작업 안에서 연속 실행하던 수정 전 구조의 측정값이다. 현재 코드는 processor에서 DELETE 두 개를 먼저 직접 실행한 뒤 INSERT 두 개와 통계 두 개를 순차 호출한다. 따라서 아래 수치를 현재 구조의 성능 측정값으로 간주하지 않는다.

동일한 DB에서 순차·병렬을 각각 한 번 예열하고 5회씩 교차 실행했다. 병렬 작업자는 4개이며 서머리 2개와 통계 조회/로그 INSERT 2개를 함께 실행했다. RAW 파싱·적재 시간은 포함하지 않는다.

| 실행 | 순차(초) | 병렬(초) |
|---|---:|---:|
| 1 | 0.5261 | 0.4030 |
| 2 | 0.5255 | 0.4058 |
| 3 | 0.5312 | 0.4227 |
| 4 | 0.6430 | 0.3871 |
| 5 | 0.6240 | 0.4628 |
| 중앙값 | 0.5312 | 0.4058 |

이 로컬 표본에서는 중앙값이 23.6% 감소했다. 데이터 규모, 인덱스, 캐시 및 DB 부하가 운영과 다르므로 운영 속도 향상을 보장하는 결과가 아니다. 과거 전체 파이프라인 실행 시간과 합산하거나 비교하지 않는다.

## 반영 전 조건

- 로그 테이블 DDL `er_dose/sql/create_er_dose_equipment_count_logs.sql`을 대상 환경에 먼저 적용해야 한다. 이번에는 임시 검증 DB에만 적용했다.
- 실행 진입점은 배치 하나를 선택하며 EUV 완료를 자동으로 기다리지 않는다. 운영에서 EUV 적재가 RAW 마지막 집계 전에 완료되도록 순서를 보장해야 한다.
- 통계 로그는 전체 배치 성공 표시가 아니다. 뒤의 순차 작업 실패 시 앞에서 저장한 통계가 남을 수 있다.

## 2026-09-17 설비별 RAW/EUV 로그 테이블 분리

`e851019` 흐름을 기준으로 복원하고 이후 DAG/SSH 변경은 제거했다. RAW 마지막 집계 위치와 기존 리로드 판단은 유지한다. 서머리·통계 전용 스레드 풀은 제거하고 DIE Yield INSERT → Root Cause INSERT → RAW 통계 → EUV 통계를 순차 실행한다. 중간 실패 시 후속 작업은 실행하지 않는다. 기존 RAW 조회·적재 스레드는 유지한다.

- RAW: `mbeat.er_dose_raw_equipment_count_log`
- EUV: `mbeat.er_dose_euv_equipment_count_log`
- 두 테이블의 컬럼: `id`, `target_date`, `eq_name`, `source_count`, `target_count`, `created_at`
- `batch_name`, `event_type`, `message`, `data` 컬럼 없이 설비별 한 행을 저장한다.
- 원천·parsed 필터와 조회 기간은 유지하며, 한쪽에만 존재하는 설비는 반대쪽 건수 0으로 기록한다. 빈 기간에는 설비 로그 행을 만들지 않는다.

`create_er_dose_equipment_count_logs.sql` 적용 후 `migrate_er_dose_equipment_count_logs.sql`로 기존 JSON/컬럼 로그를 이전한다. RAW/EUV 건수 로그만 이전하고 날짜·설비·건수·저장 시각을 보존한다. 이전한 원본을 삭제하므로 반복 실행 시 중복되지 않는다. 다른 배치/이벤트는 기존 테이블에 보존하고, 기존 테이블이 비면 제거한다. 메시지/JSON 부가 정보와 빈 배열 로그는 옮기지 않는다. 지원하지 않는 대상 payload가 있으면 원본을 보존하고 실패한다. 운영 DB에는 적용하지 않았다.

검증: 단위 테스트 106개 통과. 격리된 PostgreSQL 9.4에서 DDL 반복 적용, RAW/EUV repository의 실제 INSERT 대상, 구분 컬럼 제거, JSON/컬럼 로그 이전, bigint 건수·저장 시각 보존, 반복 이전 시 중복 방지, 다른 배치/이벤트 보존, 비어 있는 구 테이블 제거, 잘못된 payload 실패 시 원본 보존을 확인했다.

## 2026-09-18 설비 건수 일괄 INSERT

설비별 INSERT 반복 호출을 테이블별 다중 VALUES INSERT 한 번으로 변경했다. 기존 `select()` 집계, RAW/EUV 순차 저장, 서머리 DELETE·INSERT의 별도 커밋은 유지한다. SQL 값은 기존 DB 계층의 이름 매개변수 바인딩을 사용한다.

단위 테스트 108개 통과. 격리된 PostgreSQL 9.4에서 실제 `PostgresDB.execute()`를 통해 RAW 80행과 EUV 80행을 각각 저장하고, 로그 INSERT 구간의 연결·커밋·종료가 각각 총 2회임을 확인했다. 따옴표·퍼센트·한글 설비명, bigint 건수, 날짜·저장 시각, 빈 목록의 무접속 처리를 확인했다. 한 행의 NOT NULL 위반 시 그 INSERT의 다른 행도 저장되지 않았고 이미 커밋한 기록은 유지됐다. 운영 DB에는 접근하지 않았으며 처리 시간 절감 폭은 측정하지 않았다.
